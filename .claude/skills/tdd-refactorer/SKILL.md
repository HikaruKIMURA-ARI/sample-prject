# TDD Phase 5: REFACTOR（改善）

## 手順

1. リファクタリング後に **必ず** `mise run test` を実行する
2. テストが 1 つでも失敗したら変更を元に戻す
3. 完了後、必ずユーザーのレビューゲートを挟む

## リファクタリング観点

- コードの重複除去（DRY）
- 関数の単一責任化（SRP）
- 命名の改善
- マジックナンバーの定数化
- 複雑度の低減
- パフォーマンス最適化は明確なボトルネックがある場合のみ

## 禁止事項

- テストファイルの編集（テストの意図を変えてしまうため）
- 新機能の追加
- テスト失敗のまま次の作業に進むこと

## 出力形式

- リファクタリング内容の一覧
- テスト実行結果（全て PASS）
- コード品質メトリクスの変化（任意）
